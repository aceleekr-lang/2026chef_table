# 셰프의 테이블 × 강레오 — 시식권 추첨 시스템

2026 밀양 매운맛 페스티벌 「셰프의 테이블」 시식권(회차당 90매, 조절 가능) QR 응모·룰렛 추첨·현장 사용처리 웹앱.

## 파일
| 파일 | 용도 |
|---|---|
| `supabase_setup.sql` | 통합 Supabase 프로젝트에 **1회 실행** (테이블 `chef_*` + 함수) |
| `config.js` | Supabase 주소/키(이미 입력됨), 이미지 경로 |
| `index.html` | 참가자 페이지 (QR 연결 주소) — 설문 → 룰렛 → 시식권 → 스탭 PIN 사용완료 |
| `admin.html` | 관리자 페이지 — 현황·회차·설문·설정·당첨자/전화번호 추출 |
| `img/` | ChatGPT로 생성한 이미지 넣는 곳 (`IMAGE_PROMPTS.md` 참고, 없어도 동작) |

## 설치 (5분)
1. Supabase 대시보드 → **SQL Editor** → `supabase_setup.sql` 내용 전체 붙여넣기 → **Run**
2. Cloudflare Pages → Create → **Direct Upload** → 이 폴더 전체 업로드 (예: 프로젝트명 `chef-table` → `chef-table.pages.dev`)
3. QR 코드는 `https://chef-table.pages.dev/` 로 생성 (관리자는 `/admin.html`)
4. 행사 전 점검: `https://chef-table.pages.dev/?test=1` 로 접속해 응모 테스트 (테스트 데이터는 실제와 분리, 관리자에서 삭제 가능)

**초기 비밀번호**: 관리자 `chef2026` / 스탭 PIN `1111` → 관리자 「기본 설정」에서 변경 가능.

## 회차 기본값 (관리자 「회차 설정」에서 변경)
| 회차 | 사회자 멘트 | 시식 | 응모 오픈 | 응모 마감(멘트 10분 전) | 정원 |
|---|---|---|---|---|---|
| 토요일 1회차 | 10.31 15:00 | 15:30 | 10:00 | 14:50 | 90 |
| 일요일 1회차 | 11.01 13:00 | 13:30 | 10:00 | 12:50 | 90 |
| 일요일 2회차 | 11.01 15:00 | 15:30 | 10:00 | 14:50 | 90 |

- 일요일은 1·2회차 **동시 오픈** — 참가자가 회차를 골라 응모, 회차당 1번씩(1회차 낙첨 시 2회차 재도전 가능).
- 100명 중 90명은 앱 추첨, **10석은 현장/VIP 예비**로 남겨둔 설정입니다(정원 숫자만 바꾸면 됨).
- 응모 오픈 시각(10:00)은 축제 개장 시간에 맞춰 수정하세요.

## 추첨 규칙
- **1기기(폰) 1회차 1회** + **같은 전화번호 1회차 1회** (둘 다 체크).
- **한 번 당첨되면 다른 회차 응모 불가** (1인 1매).
- 당첨 확률은 오픈→마감 사이 **시간 가중 자동 조정**: 기본 25%에서 시작, 시간이 갈수록 상승, 목표 페이스(정원×경과비율)보다 느리면 가산, 너무 빠르면 감속. **마감 15분 전부터는 남은 시식권 전원 당첨**. 정원 소진 시 자동 매진. 모든 숫자는 관리자에서 조절.
- 관리자 「현황」에서 회차별 **강제 오픈/마감**, 정원 즉시 변경 가능.

## 현장 운영 (스탭)
1. 참가자가 시식존에서 폰의 시식권 화면을 보여줌 — **「토요일 1회차」처럼 회차가 크게 표시**, 티켓 번호·이름 확인.
2. 스탭이 「스탭 확인 · 사용완료」 버튼 → PIN `1111` 입력 → 「사용완료」 도장이 찍히고 재사용 불가.
3. 폰 배터리·네트워크 문제 시 관리자 「응모·당첨자」 탭에서 이름/번호로 찾아 **사용처리** 가능.
4. 노쇼 보정: 낙첨자를 「당첨전환」 버튼으로 현장에서 당첨 처리 가능(현장 대기자용).

## 당첨자 문자 발송
관리자 → 「응모·당첨자」 → 회차 선택, 「당첨자만」(필요 시 「문자수신 동의자만」) → 조회 → **「전화번호 복사」** → 문자 발송 서비스에 붙여넣기. 전체 설문 응답은 「CSV 다운로드」(엑셀에서 바로 열림).

## 설문 수정
관리자 → 「설문 편집」 JSON. 이름·휴대폰·지역·성별·연령대·개인정보 동의·문자수신 동의는 고정 항목이며, 나머지 문항은 자유롭게 추가/삭제. 저장 즉시 참가자 페이지에 반영.

## 보안 메모
- 테이블은 RLS로 잠겨 있고 모든 동작은 함수(RPC)로만 처리 — 공개 키로는 데이터 직접 조회 불가.
- 관리자 비밀번호·스탭 PIN은 서버(DB)에서 검증.
- 행사 종료 후 개인정보 파기: 관리자 「회차 설정」→ 각 회차 「응모 데이터 초기화」 (또는 SQL `delete from chef_entries;`).
